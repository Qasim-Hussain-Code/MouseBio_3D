# MouseBio_3D guide

The complete description of the application: every view, control, reference, data format and check. The [README](../README.md) gives the short overview.

MouseBio_3D is a local browser prototype for exploring laboratory mouse anatomical references, viewing illustrative and parameterized physiological models, and mapping experimental observations onto source records. It also opens user-supplied SWC morphology files as independent local line references with unverified biological identity.

Two separately identified references derive from [Digimouse](https://neuroimage.usc.edu/neuro/Digimouse_Download), a single 28 g normal nude male mouse: a lightweight tetrahedral model and a model extracted from the registered anatomical label volume. A micro-CT reference adapts the body and ten segmented organ classes, including the intestine, bone, lungs, liver and kidneys, of one native in vivo scan of a female BALB/c nu/nu mouse from [Rosenhain et al. (2018)](https://doi.org/10.1038/sdata.2018.294). A regional reference adapts the right hindlimb and pelvis of one adult female C57BL/6 mouse from [Charles et al. (2016), S1 Figure](https://doi.org/10.1371/journal.pone.0147669.s002). A separate [eMouseAtlas EMA147](https://doi.org/10.7488/ds/2167) reference preserves developmental TS23 surfaces in uncalibrated native coordinates. A separately selectable [NeuroMorpho.Org NMO_130632](https://neuromorpho.org/api/neuron/id/130632) reference supplies a source-declared adult mouse V1 layer 4 neuronal reconstruction as samples and parent-linked lines. Two regional line references supply [MVN1](https://doi.org/10.5281/zenodo.5115640) mouse cortical microvascular paths and a [MouseMapper](https://doi.org/10.1038/s41586-026-10535-2) predicted regional nerve graph from one example patch. None of these references has an accepted registration to another. The architecture includes 14 anatomical system categories; the sources do not provide complete coverage.

## Run locally

Use Linux or a WSL Ubuntu terminal in the project directory. The application requires Node.js 22.12 or later, npm and a browser with WebGL2. Geometry preparation and resource accounting require Python 3.10 or later and use only its standard library. The optional runtime setup targets Linux x64.

```bash
# Optional: install the pinned Node.js 22.23.4 runtime inside .tools.
bash scripts/setup_node.sh

# Install the exact dependency versions in package-lock.json.
bash scripts/npm.sh ci

# Open the local URL printed by the development server.
bash scripts/npm.sh run dev
```

`scripts/npm.sh` uses the project-local runtime when present and keeps the npm cache inside the project for resource accounting. On Linux Mint with a suitable Node installation, omit the optional runtime setup. The development server binds to loopback by default. No paid service, dedicated server, local language model or dedicated GPU is required by the application design.

On Windows, open a WSL Linux terminal and change to your checkout before running these commands. The checked-in GLB, native PLY, numeric SWC and polyline JSON assets and their manifests are sufficient for normal use; regeneration is optional.

A built web bundle can also be served without Node.js by `python3 scripts/serve_prototype.py` from Linux or WSL, which serves an allowlist of the bundle on loopback port 4173 without directory listings or data writes. See the [prototype guide](prototype-guide.md).

For a static host, `npm run build:host` builds the bundle and then stores each registered GLB and PLY model gzip-compressed, in place and under the same name, as `render.yaml` does on Render. A file is compressed only when its byte count and SHA-256 match its registry, the compressed stream unpacks to identical bytes and it is at least a tenth smaller. The 28 registered model files take 81,241,654 bytes instead of 194,439,203, and the living mouse model 34,178,157 bytes instead of 50,786,180. The application recognizes a gzip stream by its first two bytes, unpacks it as it downloads and checks the unpacked bytes against the same registry, so the model shown is unchanged; a plain file is read as before. Text and JSON assets are left for the host to compress. The local launcher and the release archives use the plain `npm run build` output.

A build can also be served from a subpath. With `MOUSEBIO_BASE=/MouseBio_3D/`, the bundle requests every file below that path, while its registries keep their root-relative paths, which are the paths their checksums and checks refer to. The workflow in `.github/workflows/pages.yml` makes the host build in this way on each push to the main branch and publishes it with GitHub Pages at the project address of the repository, using GitHub's own actions pinned to the commits of their releases. The local launcher serves only a plain build from the root.

While a model downloads, the view shows a bar with the share received, the megabytes that have crossed the network and, after the first second and a half, an estimate of the time left from the average rate so far. When the last byte has arrived the bar stays full while the model is checked and built. A browser keeps the files it has downloaded, so a later visit reads the model from its cache after the server confirms that the file is unchanged.

## Workbench layout

The viewer fills the workbench. The left navigator holds the **Anatomy reference** selector and three tabs. **Structures** lists source regions with search (`/`), visibility toggles and a visible-region count. **Layers** offers system layers built only from source classifications, with per-layer visibility and isolation, the **Reveal organs** preset, source groups and layer composition; categories without classified regions are listed as not represented. **Sources** holds the local SWC input, **Find anatomy**, the reference description and guided source views. On narrow screens the navigator opens as a drawer from the **Structures**, **Layers** and **Sources** toolbar buttons.

A selection toolbar appears on the viewer once something has been selected, with its name, **Focus**, **Hide** or **Show**, **Isolate** or **Restore**, **Zoom in** where a tissue has a route, and **Details**. The camera controls zoom and reset the view; with the canvas focused, arrow keys pan, `+` and `-` zoom, `Home` resets and `F` focuses the selection. Pan and zoom directions are screen directions without anatomical meaning. **Display controls** hold optional focus on selection, automatic rotation, surfaces, colours, the coat, the virtual section, the opacity of the skin, views along the display axes, labels, **Fit visible**, **Load view** and **Save view**. **Details** opens the inspector with **Structure**, **Observations** and **Source evidence** tabs.

The mark beside the name in the header and the icon of the browser tab are this whole mouse, rendered from the living model with its coat. The mark breathes, looks about, lifts its nose and takes two slow steps over twelve seconds. The icon, seen from nearer the front so that the mouse fills the square, breathes and turns its head slowly. Both keep still if the system asks for reduced motion. A button among the camera controls saves a picture of the view.

The working view is kept to the mouse and what acts on it. Explanations, sources and evidence are in the inspector, the **Sources** tab, the documents and the page behind the information button in the header. That page, **Sources and evidence**, says how many structures of the open reference are source-labelled, traced and simulated, lists every structure with its kind of evidence, its description and the works it follows, each work with a link and with the structures and deep levels that rest on it, every level of the zoom below the layers with its kind of knowledge, the procedures of the bench with their sources, what is illustrative, and the licences. The details of a structure link each work it rests on and open its entry on that page. Simulated structures carry a short `sim` mark in the labels and the list of layers at a spot, and the full evidence class in the inspector and the **Structures** list. Native-unit and source-graph calibration notices remain visible above the viewer.

## Choose an anatomical reference

Use the reference selector before exploring or importing observations. **Guided source views**, in the **Sources** tab, open a set of starting points, and **Find anatomy** routes topics such as blood vessels, nerves, brain, muscles and bones to exact source selections. The living mouse model opens first; it mixes evidence classes and is kept apart from the source references. Any reference can be opened directly with `?reference=<identifier>`. The eight bundled source references have different source-label namespaces and coordinate frames; they are alternatives, with no accepted registration or anatomical overlay between them. **Open local SWC** adds an optional user-supplied trace in a separate unknown-unit frame. A local trace is not registered to any bundled reference.

For the volume reference, select a supported region and request its finer surface in Anatomy, Living or Experiment mode. Lachrymal and adrenal glands offer an explicit processing-level selector for 0.2 mm and original-grid 0.1 mm surfaces. Regional files load selectively rather than all at startup. Changing regions or loading a view restores the base surface and default processing level. Compare uses the same base surfaces in both panels, so independent detail loads cannot introduce a surface difference between conditions. Finer sampling changes the boundary representation; it does not introduce new structures or information beyond the source image. Small features can be lost during subsampling. Both Digimouse references, their finer surfaces and the micro-CT reference are displayed by default as smoothed copies (Taubin filter; 10 iterations with lambda 0.5 and mu -0.53 for the tetrahedral reference, 40 iterations with lambda 0.6 and mu -0.61 for the volume reference, its detail files and the micro-CT surfaces) that remove the processing-grid staircase without adding resolution, with display normals diffused over neighbouring vertices so that longer terraces do not show in the shading; **Smooth voxel surfaces** in Display controls shows the source surface instead. See [viewer presentation methods](viewer-presentation.md). The volume reference has a substantially higher rendering cost, and representative integrated-graphics performance remains unverified. See [volume geometry methods](volume-geometry.md).

Source IDs must match the selected reference. The heart is `digimouse:3` in the tetrahedral model and `digimouse-volume:9` in the volume model; `digimouse-volume:3` denotes eye. Label numbers alone are not interchangeable. Imported observations are retained separately for each reference in browser memory when switching references. They are not translated between anatomies.

The micro-CT reference preserves the source file and class index in each ID, for example `rosenhain2018-m01:Organ1:5` for the intestine; the body is `rosenhain2018-m01:Bed:1`, a numbered bed-segmentation class identified as the body because it contains 99.24 percent of the organ voxels and has soft-tissue attenuation. It uses the first of the scan's two segmentation files; their Dice agreement ranges from 0.33 for spleen and 0.44 for bone to 0.90 for heart, and these values are shown as segmentation uncertainty. The dataset record declares CC0 1.0, and attribution is retained. The specimen is a female athymic, hairless nude mouse whose age and mass are not reported; its scan covers the trunk. See [micro-CT methods](microct-geometry.md).

The hindlimb model preserves the figure's exact surface names and zero-based source tessellation indices, for example `charles2016-hindlimb:0`. Its 37 muscle-named surfaces differ from the article's reported count of 39 muscles; the discrepancy is unresolved. `Foot`, `Tibia/Fibula` and `Fabellae` remain source-labelled aggregate regions. The model describes one right hindlimb and pelvis, not female whole-body anatomy or population variation. See [hindlimb geometry methods](hindlimb-geometry.md).

EMA147 preserves filename identifiers, for example `ema147:EMAPA:18601`, separately from the index in its source label volume. Only 68 of the 76 surface identifiers match the separate anatomy index; eight identifiers occur only in each inventory. `ema147:reference` has no asserted anatomical identity. Source records consistently declare TS23 but give conflicting age estimates of E15.0, 15 dpc and 14.5 dpc; no scalar age is selected. Sex, mass and explicit specimen count remain unknown. The image's reported 80 micrometre voxel spacing is not used to assign mesh units. Only 23 surfaces meet the executed closed-topology checks; known defects are retained. See [EMA147 methods](ema147-geometry.md).

For a selected EMA147 surface, **Native surface record** displays its original filename, zero-based serialization index, source EMAPA identifier when present, exact anatomy-index match when available, and indexed vertex and triangle counts. Expand **Recorded topology counts** to inspect boundary edges, nonmanifold edges, winding conflicts, noncyclic vertex links, degenerate or duplicate triangles and mesh components. These are recorded numerical source diagnostics, not calibrated measurements, anatomical review or biological connectivity. Missing and inconsistent records are disclosed.

NMO_130632 retains all numeric sample records, original sample IDs, type codes, radius fields and parent links from the checksum-bound NeuroMorpho.Org standardized file. Its single experimental structure ID is `neuromorpho:130632`; sample IDs are not separate experimental structures. **Neuronal source trace** reports graph counts and initial Float32 diagnostics. Original comment headers containing contact and machine information are omitted from the distributed derivative; required scientific attribution is preserved. Individual sex, exact age, strain, mass and explicit specimen count remain unknown. The reported 50 to 330 day range and combined Male/Female category do not establish individual characteristics. Source-reported 15 percent shrinkage is uncorrected. Neither generic SWC conventions nor an original-file axis note verifies this standardized file's physical units, anatomical orientation or original-to-standardized transform. See [neuronal morphology methods](neuronal-morphology.md).

The MVN1 paths retain declared micrometres, original edge identities, edge-local points and all 62 zero-length segments; one original graph component differs from the 12,071 indexed path components. The MouseMapper example retains every source point and ordered path in unknown units; its subregion, specimen, sex, age and laterality remain unresolved, and its components do not count nerves or cells. See the [vascular source assessment](vascular-source-assessment.md) and [nerve source assessment](nerve-source-assessment.md).

The active-source card, **Source evidence** tab and Methods dialog show declared specimen and bibliographic metadata, including species, sex, strain, age, mass, scope, citation and license. Missing fields remain Unknown. These displays do not infer specimen characteristics from a model name or supply independent verification of source declarations.

## Zooming through the layers

The living mouse model opens as it is zoomed. Scrolling towards any spot of the outside of the animal brings that spot to the middle of the view and unfolds what lies under it, from the outside inwards, in the order in which it lies there in the model: coat and skin, fat, muscles, bones, cavities and organs. Vessels and nerves are left in place through the opened layers. Each layer opens wider than the one under it and leaves the frame as the view narrows, and scrolling back closes them. The wheel, a pinch and the plus and minus keys all act the same way, and **Play** goes through the zoom at an even pace, from the whole mouse down to the quarks of a proton.

A guide on the left names the place and lists the layers at that spot, with the one being passed marked; choosing a layer goes to it. Pointing at the view names what is under the pointer, **Names** names what is in view, and a click selects what is inside or opens a new place on the coat. At the end of the zoom the same scroll [goes on down to atoms](#going-on-down-to-atoms), and **Into tissue** does so from any layer. The zoom opens the animal only while it is shown whole with its skin.

**Open a named place**, in the **Layers** tab, opens the **Whole side**, **Head**, **Neck**, **Chest**, **Abdomen**, **Hip**, **Shoulder**, **Fore limb**, **Thigh**, **Shank**, **Fore paw**, **Hind paw** or **Tail** at a fixed size, with an **Open** slider, a list of what lies there, **Fold the skin back** and **Cut into organs**.

This is a display of the model and not a dissection of an animal: the widths and timing of the openings are chosen for viewing. See [zooming through the layers](zoom-unfold.md) and [named places](all-layers.md).

## The moving mouse

The living mouse moves. The heart beats, the chest and abdomen breathe, tokens travel along the vessels and nerves, the gut moves in slow waves, and the head, tail, ears and whiskers move. It answers the pointer: its head follows it, and a touch on the closed animal makes it start and gives a short synthesized call, which can be silenced beside the view. Standing, it sits up on its hind legs to wash now and then. **Walk** sends it about the floor of the room: it goes from place to place, stops, sometimes sits up to wash, walks out of the view, and comes back later from any corner. A click on the floor sends it there. Its feet do not slide, and the head leads each turn. The tokens can be seen once the animal has been opened, and the walls of the vessels become glassy so that the tokens show inside them. Many levels below the layers move on the same clock. Rhythms run at one tenth of their real rate by default.

This is an illustration, named as such beside the view, and nothing is computed about blood, gas, nerve signals or mechanics. The rates of the heart, breathing, sniffing and whisking follow published values, and everything else, including the speed of the tokens, the walking, the washing, the size of every movement and the voice, is chosen for viewing. The voice is synthesized after published frequency bands and is not a recording. The anatomical reference and its surfaces are unchanged. The **Living** tab turns the motion or any part of it off, and sets its speed. It starts off if the system asks for reduced motion. See [illustrative motion](living-motion.md).

## Dissection practice

**Dissect** opens a bench for practising with instruments on the living mouse, with a panel that stands beside the view at every width of the window and can be hidden, so that nothing lies over the animal: a wax board under the animal, which lies on its back with its legs out to the sides or stands on its feet, a tray of instruments and a dish. A pair of gloved hands holds the instruments and works in real time: the right hand follows the pointer and the left steadies the tissue with forceps. The left button works the instrument, the right button turns the view and the wheel zooms towards the pointer. The views of a tutorial stand close enough to work in, with the hand at the edge of the view. Nearer than that, the hands lie outside it and only the instruments are seen, as through a dissecting microscope.

Clippers clip the coat, leaving the skin within bare, as a depilatory would, and the hair cut short at the edge. A scalpel divides the one layer it touches, scissors take a layer with what is bound to it, bone cutters go through bone and the muscle on it, forceps draw a layer back from the edge of a cut or take hold of an organ and move it, a blunt probe names what it touches and parts what is loose, a ligature ties a vessel, a needle and suture close every layer that lies open along a cut with a running suture of slanted loops 1 mm apart and a knot at each end, a pin marks a place, a swab cleans blood away or scrubs the skin, and a syringe goes in for as long as it is held and reports what it passed through and where its tip lies. Where a step asks for it, a syringe held in the heart fills slowly with blood. An instrument begins on what can be seen and stays on that layer, and everything under a cut is the geometry of the model. A long straight cut in the skin or the wall of the body draws a little apart, and forceps draw each side back: it folds over and lies out from the body with its pale inner side up. The front of the rib cage, once cut on both sides, lifts like a lid and turns over towards the head, and a cut along the top of the skull leaves a leaf of bone on each side that folds out. A structure can be lifted out into the dish and followed from there under the microscope into the zoom. The brain comes out whole, with its parts and the arteries on its surface. Every action can be undone, and a session can be saved as a record of what was done on the model.

Fifteen step-by-step tutorials follow the outlines of published procedures, each named and linked: opening the abdomen, finding the organs of a necropsy, collecting the spleen and the mesenteric lymph node, exposing the brain and lifting it out, tying the femoral artery, opening the abdomen and closing it again after clipping and scrubbing the skin and laying a drape, opening the chest, drawing blood from the lateral saphenous vein and slowly from the left ventricle, perfusing through the heart, and injecting into the abdomen, into a tail vein, under the skin and into the thigh. A card in the panel beside the view says for each step what to do, why, what can go wrong and what is seen, takes up the instrument and the view, marks the place on the animal, keeps a stroke to a marked line if asked, says what has fallen short, and checks what was done. A needle goes in at the angle the method gives, and for the femoral artery the leg is drawn out to the side, as the method tapes it down. The hands can show one step or the whole procedure, using the same controls as a person. This is practice on a simulated animal with illustrative hands, instruments, bleeding and tissue behaviour. It is not a protocol and no substitute for supervised training under an approved protocol. See [dissection practice](dissection-lab.md).

## Going on down to atoms

A [list of what the model holds and what it leaves out](living-mouse-coverage.md) is kept with its documents.

The zoom through the layers does not stop at the last layer. The same scroll goes on, in the same place on the screen, into the tissue of the structure under the pointer, then its cells and what they hold, and on to atoms and a proton, about thirteen orders of magnitude from the whole mouse. A list moves directly to any level, **Play** goes on down by itself, and scrolling back out past the first level, Escape or **Back to the mouse** returns to that spot. **Zoom in**, in the bar for a selected structure, goes the same way.

Every one of the 434 structures has a route: pancreas, whisker, inner ear, muscle, nerve, artery, vein, bone, fat, liver, kidney, lung, small intestine, heart, brain, skin, cartilage, tendon, serous membrane, gland, endocrine gland, thyroid, lymphoid tissue, colon, stomach, urinary lining, airway, retina, cornea, lens, tooth, testis or blood. Two levels show the tissue and its cells, each a representative example and not that part of this mouse. Some routes are the nearest kind of tissue and not an exact match.

Below the cells the way on is a cell nucleus, then chromatin, one mouse nucleosome and the atoms of its DNA. Where a level holds another way down, it is named on the view in green, and the way nearest the pointer is taken: a red cell leads on to measured atoms of mouse hemoglobin and the iron of a heme, and the bacteria of the gut lead on to the inside of a bacterium and its DNA. All of them end in a carbon atom, the inside of an atom, the nucleus of carbon-12, and a proton with its quarks. At every level, dragging turns the view, dragging with shift or the right button moves across it, and the zoom follows the pointer.

Most tissues also have a way to a measured molecule of their own, through two simulated levels of the inside of a cell: muscle and heart to a thin filament of actin and tropomyosin, skin to a part of keratin, tendon, bone, cartilage and cornea to a collagen-like peptide, brain to a mouse glutamate receptor, nerve to a potassium channel, lymphoid tissue to a mouse antibody, fat to a protein carrying a fatty acid, retina to rhodopsin, lens to a mouse crystallin, kidney to aquaporin, liver to mouse major urinary protein, lung to a domain of surfactant protein B, airway to tubulin, stomach to the gastric proton pump, thyroid to thyroglobulin with its iodine and thyroxine, testis and the other secreting glands to a whole mouse ribosome, the pancreas by an islet and a beta cell to the insulin hexamer round its zinc, the lining of the bladder and the serous membranes to a mouse claudin of the tight junction, tooth to the collagen-like peptide by way of dentine, the inner ear by hair cells and stereocilia to the mouse tip link, and a whisker by its follicle and a Merkel cell to the mouse touch channel Piezo2. Most cells can also go by a mitochondrion to mouse complex I, lymphoid tissue by a lymphocyte to the mouse immunoproteasome or by its surface to a mouse class I molecule holding a peptide, and a bacterium of the gut to a nutrient importer in its outer membrane. **Play** takes the way of the tissue it started from, and a list under the levels names the ways on from the level in view. Twenty-four entries of the Protein Data Bank supply these atoms, and each level names its species where it is not the mouse. See [the zoom below the layers](scale-journey.md).

The data of the specimen end at about 0.1 mm and magnification does not create detail, so nothing below the layers comes from that specimen, and it adds nothing to any reference. Every level marks its kind of evidence beside its name: simulated from published descriptions down to the molecules, measured in a crystal of a purified particle for the nucleosome and hemoglobin levels (Protein Data Bank entries 5B1M and 3HRW), calculated from Slater orbitals for the carbon atom, and schematic for the nucleus and the proton. **Sources** gives each level's caption and sources. See [the zoom below the layers](scale-journey.md).

## Open a local morphology

Use **Open local SWC** to select a local UTF-8 file. The simultaneous limits are 2 MiB (2,097,152 bytes), 100,000 sample records and 4,096 input bytes per line, including comment lines. Each data row contains seven whitespace-separated numeric fields: sample ID, source type code, X, Y, Z, radius and parent ID. Parents are resolved by explicit IDs, so forward references, nonconsecutive positive IDs and acyclic forests are supported. Invalid fields, duplicate or missing IDs, cycles and unsupported display ranges reject the file without replacing the current reference or observations.

The viewer draws parent-linked lines and retains original IDs and parsed numeric values. Physical units, biological identity, specimen, source license and CCF registration remain unverified; headers and filename extensions do not establish them. Radius fields are retained as metadata and do not determine line thickness. The material linewidth of 1 is a display setting, not a measured diameter. The Local trace record distinguishes source zero-length links, links collapsed after Float32 rounding and isolated samples without point glyphs. Numerical graph components do not establish cell counts, synapses or biological connectivity. No cell surface, physical measurement or physiological motion is generated.

Local trace data stay in browser memory and are not uploaded. SWC filenames and comment text are discarded from the parsed asset; its SHA-256 binds the complete original bytes, including comments and line endings. One local geometry asset is cached. Opening B replaces cached A geometry while observations remain in separate source-bound banks. Reopening A from identical original bytes restores A's observations during the same session. Reloading clears local geometry and in-memory observation banks.

Saved views contain binding and display settings, with no trace samples. Reopen the identical file and select its local reference before loading its view. Experimental observations map to the file's single trace record ID shown in the inspector; SWC node IDs are not separate experimental structure IDs. AA1624 geometry remains excluded because its source-specific licensing conflict is unresolved. The separately bundled NMO_130632 reference has its own reviewed attribution and source binding. Preserve source attribution and licensing separately; local opening does not validate permission to redistribute. See [local morphology methods](local-morphology.md) for graph rules, display precision, selection and privacy, and the [cellular source assessment](cellular-assessment.md) for deferred source reuse.

**Source sample explorer** inspects an opened local trace directly or reads the bundled NMO_130632 numeric reference after **Inspect source samples**. Look up original IDs, follow parent and paginated child IDs, or move through original source rows. Coordinates, radius fields and type codes retain their source numbers without verified physical units or biological classifications. **Focus incident links** frames existing visible, unclipped parent and child links without adding markers or changing observations. Inspector selection is transient; saved views can retain the resulting camera pose but contain no sample records. See [trace sample inspection](trace-sample-inspection.md).

**Source path explorer** reads the checked vascular or nerve derivative after **Inspect source paths**. It supports exact source path IDs, source-ordered navigation, bounded point pages and, for the vascular source, explicit endpoint and incident-path records. **Focus source path** frames retained existing segments while preserving camera direction and roll. Path selection stays out of experimental IDs, exports and saved views. See [path inspection methods](source-path-inspection.md).

## Explore and use local observations

Anatomy mode provides orbit rotation, zoom, pan, selection, search, labels, system layers, hiding and isolation, per-region opacity, display-axis clipping, reset and focus. **Aa** shows the selected region's label and **All** labels every displayed region without overlaps, with leader lines to display bounds centres. Selecting a hidden or fully transparent region makes it visible again. The viewer has a single white background. In both Digimouse references the body region opens as opaque pink skin, matching the hairless nude source specimens; the micro-CT body, cut by its scanned field, opens see-through and can be made opaque. All three are displayed with the dorsal side up above a soft ground shadow; the dorsal direction is inferred from the positions of the skeleton, kidneys, heart and bladder, without verifying the source axes or laterality. The **Skin** control sets its opacity, and selecting an internal region or opening Living, Experiment or Compare makes opaque skin see-through. The viewer uses image-based studio lighting, neutral tone mapping, uniform tissue-like surface materials and a view-angle dependent translucent body envelope; the selected region receives a rim highlight. Regions use a tissue-like display colour scheme keyed by source label words; **Colours** in Display controls switches to the manifest colours, and source-declared figure colours are kept in both schemes. These are presentation conventions without optical or anatomical meaning; see [viewer presentation methods](viewer-presentation.md). **Reveal organs**, where available, makes the existing body envelope and skeleton translucent; **Show all** restores default visibility. Layer counts follow source classifications, hidden flags and opacity; categories can overlap or contain aggregate regions, and clipping and occlusion are not counted. Clipping exposes existing surfaces. On the volume reference the cut face can instead show source images of the same specimen: **Cut face** in Display controls chooses the specimen photograph, CT or none, **Cut through the specimen** in Layers opens a central section facing the camera, and **Open specimen photographs** leads there from the lightweight reference. These are measured images on the labels' source grid, masked to the labelled body. The photographs show frozen postmortem tissue at the block face, where blood-rich organs appear nearly black, so they are not the appearance of a living mouse. Other references have no section images and their clipping does not reconstruct tissue. See [section image methods](section-images.md). While the body surface is at least 95% opaque and uncut, the regions inside it are neither drawn nor picked, because sampling would otherwise show them through gaps that the source does not have; see [viewer presentation](viewer-presentation.md).

For reviewed bundled inventories, **Isolate a source group** selects the available brain, aggregate skeleton, source muscle regions or other organs in the Digimouse references. The volume reference also groups eyes and lachrymal glands. The micro-CT reference groups its bone, its organs and its liver, stomach and intestine. Hindlimb groups expose its existing muscle, bone or aggregate, and tendon surfaces. EMA147 also offers 75 named surfaces without the skin-labelled and unannotated reference files, 15 selected neural-labelled surfaces, six filenames explicitly naming bone or cartilage, eight explicit tissue/layer labels, selected vessel-labelled surfaces and trigeminal-labelled surfaces. These narrow selections overlap and do not establish formal system classifications or complete coverage. A group view hides other regions, restores its members' opacity, clears surface clipping and frames their existing bounds. **Fit visible regions** reframes the visible selection while retaining viewing direction and camera roll. Group controls retain observations and background. Groups select existing source geometry, including the complete NMO_130632 line reference; they add no structures, biological resolution or connectivity claims. See [anatomical display groups](anatomy-groups.md).

**Compose source layers** combines several available groups into one selection, counting overlapping members once. Apply makes the selected regions opaque and either hides the other regions or fades them to the smaller of their source-default opacity and 15%. It clears clipping, restores base surfaces and frames the selected bounds while retaining camera direction, roll, observations and background. **Show all** restores source defaults. Saved views preserve the resulting visibility and opacity; the draft group checkboxes are not stored. See [source layer composition](source-layers.md).

Living mode separates four kinds of content. Each carries its own classification.

1. **Illustrative motion.** Separately controlled cardiac and respiratory surface deformations for the Digimouse references, with pause and display speed. Amplitudes and periods are arbitrary display settings without physiological calibration. The living mouse model has its own, described under [the moving mouse](#the-moving-mouse).
2. **Schematic routes.** For the Digimouse references, **Blood circulation routes** animate tracers through the pulmonary, systemic and hepatic portal circuits between existing source regions, and **Nerve signalling routes** animate pulses along vagal, trigeminal motor and optic routes. The tetrahedral reference has 30 connectors and the volume reference 26; routes whose organs are not segmented are omitted. Connectors are display curves between surface anchors, not vessel or nerve geometry, and tracer and pulse speeds are arbitrary. Each route is an educational simplification of organ-level anatomy from cited OpenStax *Anatomy and Physiology 2e* sections, with recorded inferences where a nucleus-level origin is assigned to an undivided source label. **Selected region only** restricts the display, the inspector lists the selected region's routes with their basis and references, and **Download route table** exports the resolved routes. Route layer choices are not stored in view files. See [schematic route methods](living-circuits.md).
3. **Regional path models.** On the MVN1 reference, **Compute path flow** applies the steady Hagen-Poiseuille relation to one retained source path with user-entered radius, pressure drop and viscosity; tracers follow the computed mean velocity. On the MouseMapper reference, **Run nerve signal model** computes a generic dimensionless FitzHugh-Nagumo cable in a cancellable worker and maps it onto one source path by normalized length. Neither model is calibrated to mouse measurements, and results can be exported with their source binding. See [path flow methods](path-flow-model.md) and [excitable cable methods](excitable-cable-model.md).
4. **Cardiac cell model.** An independent 41-state Bondarenko apical mouse ventricular-cell model computes membrane voltage and calcium handling at the source temperature of 298 K, with archived-source and balanced-transition equation variants disclosed before calculation. It is independent of anatomical views and observations. See [cardiac cell methods](cardiac-cell-model.md).

Hindlimb, EMA147, NMO_130632 and local traces have no implemented motion or routes. EMA147 vascular-labelled surfaces do not establish complete connectivity or a flow model. No whole-body blood-flow simulation, measured conduction or independently validated physiology is implemented. Other physiological systems have extension interfaces without implemented models.

Experiment mode imports local CSV or schema-conforming JSON, validates source IDs, measurements, units, subjects, conditions and labelled time points, and maps group means onto the selected reference. It reports subject counts and sample standard deviations. Compare mode shows two conditions on the same selected reference geometry with synchronized cameras and a common quantitative scale. Differences are descriptive; no treatment, sex, developmental or disease anatomy is generated. When no data or pending import would be displaced, **Try synthetic comparison** loads a labelled fictional walkthrough whose synthetic origin persists in exports; its values are not animal observations.

Observations stay in browser memory. Reloading clears them; replacing or clearing a reference's dataset affects its local observations. No remote upload, analytics or automatic research-data transmission is implemented. Dataset provenance controls preserve a user-declared title, source reference, license, sampling notes and origin in JSON exports. These declarations are not independently verified. Synthetic examples are identified explicitly.

Save view and Load view preserve display settings separately from observations. Files bind selection, visibility, effective opacity, clipping, labels, background, living controls and an optional camera pose to the selected atlas ID, asset checksum and coordinate-frame ID. Incompatible files are rejected atomically. Older files that record the retired dark background, or no background, load with the white background after the same binding checks. Loading a view retains current observations. View files do not reproduce an entire experimental session or animation phase; see [view-state methods](view-state.md).

For the tetrahedral reference, the inspector presents 13 proposed associations with ten generic Mouse Adult Anatomy terms and identifies four unmapped source regions. They retain proposed, computational-inference status, references and limitations. These unreviewed label associations add no anatomy and do not transfer automatically to other references or experimental IDs. See [ontology methods](ontology-mapping.md).

## Experimental format

CSV files require exactly these columns:

```csv
structure_id,measurement,value,unit,replicate,condition,time_point
```

Use an available source ID from the selected reference. Each row represents one biological subject, structure, measurement, condition and time point. Resolve technical replicates before import. Numeric time points need units, for example `24 h`; categorical labels such as `baseline` are accepted. Limits are 5 MiB and 20,000 observations. The normalized JSON export must also fit 5 MiB with reserved provenance space, so a smaller CSV can exceed the normalized budget. Units use a declared vocabulary and are never converted implicitly.

No measured experimental observations are bundled. Test fixtures are synthetic software inputs. See the [data model and methods](data-model.md) for the JSON schema, validation, descriptive statistics and interpretation limits.

## Scientific limits and resources

The living mouse model is a constructed model. Its posture, coat and every structure marked simulated are estimates that follow published descriptions and are not measured, and nerves follow a description of the rat. Traced structures are found in the source images by the colour and density criteria given in the [living mouse methods](living-mouse.md) and have not been reviewed by an anatomist, the boundaries and names of parts marked "division estimated" are estimates, and the branches of the simulated trees follow no real vessel or airway. Its frame has no accepted registration to the other references, which keep their scanned posture. Use **From the outside in** in Layers to peel the model, and **Cut through the body** to open a section, whose flat colours are a display convention.

The volume reference separates six brain regions; its skeleton remains aggregate. The separate hindlimb reference includes named muscles and some bones, with other bony labels remaining aggregate. EMA147 adds developmental source-labelled structures including an aorta, vena cava, basilar artery, trigeminal V nerve and ganglion. These are incomplete embryonic surfaces, not complete vascular or peripheral-neural coverage. The MVN1 and MouseMapper sources are regional line geometry from a cortical sample and a predicted nerve patch, and the schematic Living routes are display connectors rather than vessel or nerve anatomy. Complete adult whole-body vessels and nerves remain unavailable. Limited source-labelled developmental tissue and layer surfaces are present. The independent NMO_130632 neuronal tracing adds source samples and parent links, and user-supplied SWC line geometry can be displayed locally. Measured cellular surfaces, independently verified cell identity, comprehensive cellular coverage and microscopic histological reconstruction are not supplied. The Digimouse skin or body envelope is residual bulk tissue, not independently segmented skin layers. Paired Digimouse labels do not establish laterality. Female whole-body, population-average and disease-specific anatomy are not supplied. Camera magnification adds no biological resolution.

Native anatomical axis directions and physical calibration remain independently unverified. EMA147 mesh units, NMO_130632 coordinates and local trace coordinate units are explicitly unknown; none receives an inferred metric conversion. Display-axis controls carry no anatomical direction claim, and calibrated measurements are unavailable. Source frames must not be combined by matching coordinates, numbers or bounding boxes. Numerical topology checks are not independent anatomical review or physiological validation.

Bundled scientific assets total 311,649,834 bytes across 61 files before manifests and notices: GLB and PLY surfaces of 196,835,779 bytes, including the living mouse model at 53,182,756 bytes; section images of 56,423,230 bytes; the numeric neuronal SWC and two polyline derivatives of 38,836,114 bytes; the centre lines of the living mouse, of 2,665,635 bytes; and the atoms of the zoom below the layers, of 16,889,076 bytes. User-supplied traces are separate. This excludes dependencies, caches, raw archives, manifests and Git metadata. `resource_usage.py` includes those project resources against a conservative 10,000,000,000-byte budget; run it after installations or dataset changes. Linux Mint with 16 GB RAM and integrated graphics is the target, not an established hardware benchmark.

The [scientific resource review](scientific-resources.md), [advanced source review](advanced-resources.md) and [resource registry](../data/resource-registry.json) separate reviewed candidates from imported anatomy. The authoritative manifests are [tetrahedral atlas](../public/atlas/atlas.json), [volume atlas](../public/atlas-volume/atlas.json), [regional detail index](../public/atlas-volume/detail-index.json), [hindlimb atlas](../public/atlas-hindlimb/atlas.json), [EMA147 native surfaces](../public/atlas-ema147/atlas.json) and [NMO_130632 neuronal trace](../public/atlas-neuron/atlas.json). See [development status](development-status.md) for remaining work.

The zoom below the layers is representative and is not data from the specimen. Its simulated levels are generated illustrations with estimated sizes and counts, its crystal structure is of a purified particle whose DNA the entry records as human in origin, its electron density uses Slater orbitals, which are an approximation, and its two deepest levels are schematic drawings. It has not been independently reviewed.
