# MouseBio_3D v0.5.0

## Regional hindlimb reference

The application adds an independently selected reference from Charles et al. (2016), S1 Figure: one adult female C57BL/6 right hindlimb and pelvis. The model preserves 44 source-labelled surfaces, including 37 muscle-named regions, one patellar tendon and six bony or aggregate regions. It contains 540,165 vertices and 664,210 triangles in a 20,981,512-byte GLB.

The source paper reports 39 muscles, while the figure contains 37 muscle-named surfaces. This discrepancy is unresolved. Foot, Tibia/Fibula and Fabellae remain source-labelled aggregates. No extra structures or ontology mappings are inferred. The source unit is converted uniformly from millimetres to metres; anatomical directions and physical calibration remain independently unverified. No accepted transform connects this regional specimen to either Digimouse reference.

Source-specific groups isolate the existing muscle, bone or aggregate, and tendon surfaces. Reference switching retains observations separately, and comparison uses the same selected geometry in both panels. No physiological motion is implemented for the hindlimb. The source's CC BY 4.0 attribution and conversion notice accompany the asset; Digimouse retains its separate CC BY-SA 4.0 terms.

## Verification

All 149 JavaScript and simulated DOM tests and all 54 Python tests passed. The TypeScript production build, dependency notice checks and all six HTTP distribution checks passed. The converter reproduced the GLB checksum, and numerical and actual Three.js loader checks covered all 44 surfaces. Because the Windows-mounted workspace stalled in WSL, integration checks used a local WSL temporary copy whose 107 source, test, configuration and asset files were verified against the workspace by SHA-256.

The Windows computer-use helper timed out during initialization, so these results do not establish actual browser pixels, interactions or representative GPU performance. They do not constitute independent anatomical review or physiological validation.

The normal WSL workspace resource scan stalled on the Windows mount. A separate Windows metadata scan estimated cluster-rounded file sizes with an allowance for entries, and included the full WSL temporary-filesystem capacity; that conservative estimate stayed below the 10 GB project budget. It does not inspect NTFS alternate data streams or follow symbolic links, and is not a precise allocated-size measurement.
