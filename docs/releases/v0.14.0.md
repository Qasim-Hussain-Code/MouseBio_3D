# v0.14.0 presentation candidate

This release changes how the existing references are displayed. No anatomical asset, manifest, identifier, coordinate frame or licence changed. [The prototype guide](../prototype-guide.md) describes the complete current application; [viewer presentation methods](../viewer-presentation.md) records every convention introduced here.

## Implemented behavior

- Image-based studio lighting (prefiltered RoomEnvironment), neutral tone mapping, uniform clearcoat tissue materials, a gradient page background behind a transparent canvas, a raised three-quarter default pose and optional automatic rotation that stops at the first pointer interaction.
- The body envelope fades where it faces the camera and keeps its silhouette; its default opacity in the tetrahedral reference rose from 0.1 to 0.22. The selected region is marked by a rim light instead of a green emissive tint.
- Voxel-derived Digimouse surfaces are displayed as Taubin-smoothed copies computed in a Web Worker after loading (10 passes, lambda 0.5, mu -0.53 for the tetrahedral reference; 40 passes, lambda 0.6, mu -0.61 for the volume reference and its finer surfaces). The source surface stays in memory and can be shown instead; schematic route anchors keep using source vertices.
- A tissue-like display colour scheme keyed by source label words replaces the manifest colours by default; the manifest colours remain selectable, and source-declared figure colours such as the hindlimb surfaces are kept in both schemes.
- **All** labels every displayed region without overlaps, with leader lines to display bounds centres, in addition to the selected label.
- The interface chrome uses a neutral palette with darker body text and the structure list shows the active display colours.

## Executed verification

405 JavaScript and simulated DOM cases passed with no failures or skips on the committed source, including new cases for the shading hooks, the smoothing filter on synthetic and actual surfaces, the display palette against every manifest and the label layout. TypeScript, dependency notices and the production build passed. The Python release and publication suites passed; Python processing, assets and manifests are unchanged. The actual-asset smoothing check records the largest departures of the display copies from their sources: 0.54 mm vertex displacement and 3.28 percent enclosed-volume change in a 388-triangle tetrahedral muscle sliver, at most 0.31 mm and 0.19 percent for the volume base heart, liver and lungs, and 0.15 mm and 0.25 percent for a 0.2 mm regional surface.

A headless Chrome session with software WebGL rendered the restyled interface and the smoothed, recoloured references; its details are recorded in [acceptance criteria](../acceptance.md). Screenshots were inspected visually. These observations are software-rendering evidence, not representative GPU, memory or frame-rate measurements, and not anatomical review.

## Scientific and operational limits

Lighting, materials, smoothing parameters, colours, label anchors and the default pose are presentation conventions. Smoothing adds no resolution and leaves residual terraces on the largest volume surfaces at close range; colours approximate fresh-tissue appearance and are not measured; label anchors are display bounds centres, not anatomical centroids. Source calibration, orientation, developmental age conflicts, topology defects and the absence of registration between references retain their documented limits. Representative hardware measurement, keyboard and assistive-technology review, and independent anatomical and physiological review remain outstanding.
