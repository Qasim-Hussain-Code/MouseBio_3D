# MouseBio_3D v0.8.0

## Browser-local morphology

Open local SWC reads a user-selected morphology file as a separate in-memory reference. The reader preserves numeric sample IDs, type codes, coordinates, radii, explicit parent IDs and row order. It accepts forward parent references and acyclic forests without inferring biological identity or linking the trace to a bundled anatomical reference. No measured morphology is bundled by this release.

The reader bounds input at 2 MiB, 100,000 sample records and 4,096 UTF-8 bytes per line. Duplicate IDs, missing parents, cycles, invalid fields and unsupported numeric ranges reject the complete import. Failures preserve the current reference, observations and view. Newer file or reference choices supersede older reads. Fixed read-error messages omit arbitrary private error text.

Declared parent links are indexed line segments, with no radius-derived thickness, root spheres, completed surfaces, synapses or physiological model. Isolated samples remain in the numeric asset without point glyphs. Source graph counts do not establish cells or specimens. Coordinates, source attribution, units, license and biological identity remain unverified.

Initial Float32 serialization diagnostics are distinct from subsequent display preparation. Recentring can introduce additional rounding and coincident display links, including when a small source branch spans a much larger coordinate range. These figures are neither total rendering-error bounds nor physical accuracy estimates. Parsed source values are unchanged. Line selection applies a display tolerance after clipping and does not estimate physical thickness.

The exact original file bytes determine SHA-256 source identity, including ignored comments and line endings. Filenames and comment text are not retained in the parsed asset. One local geometry asset is cached; checksum-bound observation banks remain separate. Reopening the identical file can restore its observations during the same session, within the bank capacity. Views contain binding and display settings, not sample rows; reopen the source before restoring a view. Reloading clears local traces and observations.

The four bundled references retain their independent frames, assets and licenses. The separate AA1624 assessment now records an acquired ignored source file and an unresolved source-specific licensing conflict. Its morphology remains excluded from application assets and publication.

## Publication checks

Release packaging accepts a source checkout without a project README while retaining license, notice and scientific-asset requirements. Historical publication checks apply local-only path rules before blob deduplication and inspect bounded commit and annotated-tag metadata. They remain read-only and report finding types and counts without matched contact or credential values.

The publication checkout retains the cleaned source history and excludes the private local guide and local instructions. The development checkout and its original history remain on the device. Repository and milestone release remain private for review; content checks do not resolve previously retained GitHub commit caches or change visibility.

## Verification and limits

All 213 JavaScript and simulated DOM cases and all 69 Python cases passed without failures or skips. TypeScript checking, dependency notices and the production build passed. The suites cover source bounds, immutable graph records, line geometry, initial and display-preparation precision, clipping and picking, source identity, stale imports, observation restoration, private errors and saved-view bindings. Publication cases exercise optional README packaging, historical local paths and modes, bounded metadata, nested tags and value-free findings without rewriting history.

Checks run in a native WSL temporary copy; reviewed source blobs and public asset hashes are compared against the development snapshot before publication. Resource accounting includes ignored local sources, dependencies, tools, caches, intermediates, release artifacts and Git metadata. The conservative host estimate includes the full WSL temporary-filesystem capacity against the 10 GB budget; it is not a precise allocation measurement and does not inspect NTFS alternate data streams.

Numerical parser, geometry and simulated DOM checks are separate from browser rendering. Windows computer-use inspection was stopped because the runtime could not verify the current browser URL well enough to enforce its policy; no browser-rendering success is claimed. Pointer interaction, responsive layout, WebGL pixels, memory and representative GPU performance remain unverified. Independent anatomical review, physical calibration, registration and quantitative physiology remain unresolved.
