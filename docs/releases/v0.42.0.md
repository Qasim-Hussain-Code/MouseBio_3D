# v0.42.0 compressed models and a loading bar

A release that shortens the first download of the application from a static host and shows how far it has come. The models, their geometry and their registered checksums are unchanged. This version is published on the main branch, from which the hosted site is built; no packaged release archives were made for it, and v0.41.1 remains the latest packaged release.

## Implemented behavior

- **Compressed models on a static host:** `npm run build:host`, which `render.yaml` now runs, builds the bundle and stores each registered GLB and PLY model gzip-compressed, in place and under the same name. A file is compressed only when its byte count and SHA-256 match its registry, the compressed stream unpacks to identical bytes and it is at least a tenth smaller. The 28 registered model files take 81,331,442 bytes instead of 194,544,603; the living mouse model, which opens first, takes 34,267,945 bytes instead of 50,891,580.
- **Unpacking in the browser:** the bounded fetch of a model recognizes a gzip stream by its first two bytes and unpacks it as it downloads. The unpacked bytes must match the registered byte count and SHA-256 exactly, as before, so compression cannot change the model shown. A plain file is read as before, and a host that has already decoded the file is handled the same way. A browser without `DecompressionStream` reports that it cannot unpack the model.
- **Loading bar:** while a model downloads, the view shows a bar with the share received, the megabytes that have crossed the network and, after the first second and a half, an estimate of the time left from the average rate so far. When the last byte has arrived the bar stays full while the model is checked and built. The bar states its value to assistive technology; its figures are not read out on every change.

## Limits

- The plain `npm run build` output, the local launcher and the release archives keep uncompressed files. Text and JSON assets are left for the host to compress.
- Download times depend on the network and the host. The estimate of time left is an average of the rate so far, not a prediction.
- The model and its limits are unchanged. They are recorded in [living mouse methods](../living-mouse.md) and [acceptance](../acceptance.md).
