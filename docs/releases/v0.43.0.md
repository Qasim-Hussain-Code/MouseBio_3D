# v0.43.0 serving from a subpath and GitHub Pages

A release that lets the application be served below a subpath of a site, and publishes it with GitHub Pages at the project address of the repository. The models, their geometry and their registered checksums are unchanged. This version is published on the main branch without packaged release archives; v0.41.1 remains the latest packaged release.

## Implemented behavior

- **Subpath builds:** with `MOUSEBIO_BASE` set, for example to `/MouseBio_3D/`, the build places its scripts, styles, favicon and images below that path, and the application requests every registry file, model, section image, centre line and molecule below it. The registries keep their root-relative paths, which are what their checksums and checks refer to. An unsafe value stops the build. Without the variable the site is served from the root, as before.
- **GitHub Pages:** the workflow in `.github/workflows/pages.yml` runs `npm ci` and the host build under `/MouseBio_3D/` on each push to the main branch, then publishes the result with GitHub Pages. It uses GitHub's own actions pinned to the commits of their releases, and its permissions are limited to reading the repository and publishing Pages.
- **Home link:** the name in the header leads to the start of the application wherever it is served.

## Limits

- The local launcher serves only a plain build from the root.
- GitHub Pages has a soft limit of 100 GB of transfer a month, and a first visit to the application downloads about 35 MB.
- The model and its limits are unchanged. They are recorded in [living mouse methods](../living-mouse.md) and [acceptance](../acceptance.md).
